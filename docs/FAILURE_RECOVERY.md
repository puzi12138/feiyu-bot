# 小黑盒与 B站故障恢复边界

本次归档同步已部署的故障分类、一次新内容尝试、小黑盒图片解析、网页评论兼容与自有代理连接池修复，以及 B站设备字段声明。它不携带原环境的账号、配置、授权、事故、账本或发送回执，也不会为新环境自动开启业务。

## 一次新内容尝试

符合固定错误类别的首次模型或识图连接、超时故障，在原条终结并取得故障通知的发送确认回执后，可立即安排一次未处理的新帖子或新视频，不等待常规浏览间隔。普通浏览频率不变，原有时段、配额、授权、来源验证与去重检查仍然有效。

- 小黑盒同一帖的识图与评论共用一次机会，不能分阶段重复领取。
- B站必须重新发现并实际观看新视频，再为同一视频生成私人手账；不能用旧视频记录冒充新尝试。
- 新内容再次失败、结果不明、通知未确认或记录异常时，保守暂停。没有合格内容时不循环调用模型。
- 机会在执行前持久登记；旧机会不会因重启而重新领取。启动时还须验证调度与故障处理的绑定完整性。

账号、权限、限流及发送结果不明不属于立即换新内容的放行条件。结果不明应先核对原回执；不能重新发送原评论，也不能把宽泛的“模型失败”标签当作已确认的连接故障。

平台明确拒绝单条评论内容时，原条可被单独终结；只有对应通知确认且其他保护通过，才能继续其他内容。恢复暂停不回放旧任务。

## 小黑盒图片与网页评论

官方图片域名在系统解析全部落入指定虚拟地址段时，使用既有安全 HTTPS 备用解析。只有明确的传输超时或连接重置可退避一次：每次上限 5 秒，间隔 0.25 秒，两次及清理共用 10.25 秒预算。证书、TLS、HTTP、JSON、DNS 校验错误不因此放行；仍检查域名、地址及取消信号。

错误诊断记录固定阶段、类别和尝试次数，不把图片地址或底层响应正文加入诊断字段。网页评论签名同步当前官方网页的 v16 协议；协议常量来自公开网页，不是账号凭据。该路径需要在共享 Python 环境安装 `cryptography>=41.0`，使用其 AES-GCM 支持；此依赖已列在 B站插件的 `requirements.txt`，管家插件没有独立依赖清单，单独取用时须补齐。接口规则仍可能随平台变化。

## TLS 握手失败与连接池耗尽

模型连接失败与平台轮询超时需要分开定位。经 httpcore/AnyIO 转换且上下文被抑制的 TLS EOF，现在会在受限异常链中识别；只有满足原有严格条件的错误才能进入一次新内容尝试。证书、账号、限流、未知发送及非白名单错误继续阻断，不因发现 EOF 就重试原请求。

另一类故障是客户端内部 `PoolTimeout`：请求尚在等连接池空位，不能据此认定它已发到平台。已核实的触发路径是 HTTP CONNECT 成功后 TLS 握手失败，`httpcore 1.0.9` 中底层流已经关闭，但内部隧道仍标记为 ACTIVE；这类槽位累积后会堵住后续轮询。

本修复只包装小黑盒适配器自有 HTTP 代理池的连接工厂：

- CONNECT/TLS 尚未完成即异常时，关闭这个失败隧道，并原样传播异常。业务请求已经开始的路径保持原行为，不增加发送重试。
- 对既有残留，只在重新核验精确连接类型、TLS 未完成、底层流已关闭、没有请求指派且三个相关锁均空闲时逐个关闭。未知、仍开放或在途连接不清理。
- 不清空整个客户端，不扩大连接池，不修改全局 httpcore 或其他模型客户端。原超时、TLS 证书验证和未知结果不重发保护保持。

这是针对特定内部接口的兼容补丁：当前严格要求 `httpx == 0.28.1`、`httpcore == 1.0.9`，以及既有 loopback HTTP 代理 `http://127.0.0.1:7897` 和相符的自有客户端结构。它不会自动适配其他依赖版本、代理端口或连接池实现；不满足条件会拒绝安装此包装。新环境须先核对这些条件并做离线兼容验证，不能简单删除版本或结构校验来强行运行。

诊断分别保留模型、图片解析、投递和轮询的固定阶段、错误类别、受限异常链及池计数，不在这些字段中记录图片地址、错误正文、请求内容或凭据。诊断结果不会自行解除故障暂停或回放历史任务。

## B站设备字段

配置 Schema 声明 `BUVID3`、`BUVID4`，默认均为空字符串，供既有流程缓存设备标识，避免配置规范化丢弃这些字段。公开仓库不附带实际设备值、Cookie 或账号配置。

B站视频视觉入口仍沿用 [共享分镜分析路径](BILI_VIDEO_PIPELINE.md)。本次恢复逻辑没有改成另一套视频分析服务。

## 源码入口与验证范围

- `plugins/feiyu_steward/incident_policy.py`、`incident_hooks.py`：故障分类、通知和接线。
- `plugins/feiyu_steward/new_content_retry.py`：持久化的一次新内容机会。
- `plugins/feiyu_steward/bili_immediate_retry.py`、`bili_journal_review.py`：B站即时发现、观看与同视频手账衔接。
- `plugins/astrbot_plugin_xiaoheihe_adapter/xiaoheihe/feiyu_new_content_retry.py`、`adapter.py`：小黑盒调度接入。
- `plugins/astrbot_plugin_xiaoheihe_adapter/xiaoheihe/image_dns.py`、`security.py`：受限图片解析与诊断。
- `plugins/feiyu_steward/heybox_write.py`：网页评论签名、自有代理连接工厂与失败握手清理。
- `plugins/feiyu_steward/failure_diagnostics.py`：固定错误类别、受限异常链和连接池诊断。
- `plugins/astrbot_plugin_bilibili_ai_bot/core/proactive.py`、`schedule_mixin.py`：B站调度及观看接入。

修复在原部署的 Python 3.12 环境通过相应回归、连接池复现、失败隧道清理和并发安装检查；不宣称 Python 3.10 兼容或所有新环境都已验证。小黑盒图片处理到评论发送此前曾取得自然业务回执；即时换新内容调度也曾自然触发，但后继投递结果不明，不能称其完整发送链已成功。

本次连接池修复后，原部署的自然轮询已恢复，连续失败计数自然归零；相关暂停经单独核验后解除，历史失败和未知结果保持。同步时仍未核得本次恢复后的新评论回执，不能把轮询恢复等同于新评论发表成功，也不承诺外部模型连接永久稳定。源码检查、通知确认、平台接口回执及平台页面读回是不同层次的证据。

归档仍需按 [安装与配置说明](SETUP.md) 补齐依赖和私密配置。不要复制历史事故、授权或发送账本到新身份，也不要通过重发结果未知的业务来测试部署。
