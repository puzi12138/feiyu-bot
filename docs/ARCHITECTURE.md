# 架构与依赖边界

本仓库保存的是应用扩展与集成源码。AstrBot、平台客户端、模型服务和本地媒体工具分别提供宿主、通信、推理与处理能力，需要按来源锁和各自许可重新取得。

公开归档包含 10 个插件的源码。翻唱、图像陪伴、私聊陪伴和 Remember You 四个插件未确认再分发许可，仅记录外部来源，源码和本地修改均不包含。下面的调用关系包含系统设计中的外部依赖，不代表本仓库足以恢复所有功能。

## 调用关系

```text
平台事件 / 使用者请求
        ↓
AstrBot：会话路由、上下文、模型、工具与插件调度
        ↓
plugins/：内容读取、陪伴、记忆、媒体和管理能力
        ↓
feiyu_steward：身份与会话权限、业务门禁、发送意图与回执
        ↓
平台适配器 / 原生桥 / 本地服务 / 模型服务
```

图中表示主要职责关系，不表示所有插件都必经管家或全部底层出口都已覆盖保护。平台连接、插件加载、模型可用与真实投递是不同状态。

## 分层

| 层 | 位置 | 职责与边界 |
| --- | --- | --- |
| 宿主修改 | `upstream/overlays/AstrBot/` | 在锁定上游基线之上的少量宿主源码替换；完整宿主需另行取得 |
| 功能插件 | `plugins/` | 10 个 AstrBot 插件的源码、配置 schema、依赖声明及必要前端源码；另有四个仅记录来源的外部插件 |
| 业务协调 | `plugins/feiyu_steward/` | 会话权限、资源与时段限制、公开内容处理、业务状态及受控投递 |
| 本地脚本 | `scripts/` | 启停、进程定位、健康检查及媒体/服务封装；执行前需适配路径和配置 |
| 原生集成 | `integrations/native-bridge/` | QQ 原生接口封装、加载辅助、媒体和语音桥；依赖另行取得的兼容运行包 |
| 其他依赖 | `upstream/overlays/`、`upstream/snapshots/` | 有基线的替换文件，或缺少可核对 Git 基线时保存的必要源码 |
| 本地服务 | `upstream/local/` | 账单解析、浏览器封装和音乐服务等本地接口；不包含账号会话和账单 |

`upstream/DEPENDENCIES.lock.json` 记录可核对的来源、版本与缺口。`overlays/` 只保存需替换的文件，不含原始差异中被删除的私人内容。`snapshots/` 是经过筛选的源码快照，不能据此宣称与某个上游提交完全一致。

## 外部能力

- QQ 与 SnowLuma：独立安装与配置；客户端、发行包及登录状态不在仓库中。
- 公开平台：B站、小黑盒、贴吧、QQ 空间等依赖外部接口及独立账号授权；源码存在不等于平台允许或已授权操作。
- 模型与媒体：语言/视觉/图片/语音服务、FFmpeg、转录、翻唱与本地图像组件按所选功能单独安装；不分发权重、声音和素材。
- 内容学习：人格、记忆、阅读和手账服务可能产生私人数据；只保存源码结构，不迁入原有内容。

原生桥的启动辅助存在来源和文件哈希校验。修改源码、重新取得上游或调整构建会改变校验值，重建时应审核新的完整文件集合并生成匹配清单，保留完整性校验。缺少可核对的上游集成基线时，原生链路仍属重建缺口。

## 数据与行为

新环境使用独立、空白的运行目录。配置、授权、账本、队列、回执、聊天、记忆、日志、缓存与媒体均为运行数据，不属于本源码归档。

部分已接入路径的出站业务设计包括发送前持久登记、去重、发送后记录回执，以及失败或未知结果的阻断。归档没有保留原有运行账本，不能用于接续或重放旧任务。新的使用者需要按自己的业务建立独立状态；未知结果不能被当作失败后自动重发。

模板保持外发与自动任务关闭或未授权。只有使用者逐项配置并明确启用后，相关路径才应进入实际运行。克隆仓库、安装插件或读取状态都不构成对外操作授权。
