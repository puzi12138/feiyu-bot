# 重新安装与配置

本仓库没有经过全新环境部署验收。下列步骤说明重建所需材料和顺序；具体命令以对应锁定版本的上游安装文档、项目依赖清单和模板说明为准。

公开归档只包含 10 个插件源码。`astrbot_plugin_ai_cover`、`astrbot_plugin_image_companion`、`astrbot_plugin_private_companion` 和 `astrbot_plugin_remember_you` 未确认再分发许可，只有外部来源记录，不包含其源码或本地修改。使用者需另行核对条款并取得需要的组件；即使取得上游，也不能据此恢复未导出的本地修改与相关完整功能。

## 1. 准备独立环境

在自行选择的新目录安装与目标依赖兼容的 Python、Node.js、PowerShell 和 Git。媒体功能按需安装 FFmpeg、ffprobe 等工具。QQ、SnowLuma、模型服务及其他二进制从各自合法来源取得，不从本仓库还原。

新建空白配置和数据目录。不要将现有生产配置、浏览器档案、数据库、队列或授权文件复制进源码仓库。

## 2. 取得上游与源码

1. 阅读 [`upstream/DEPENDENCIES.lock.json`](../upstream/DEPENDENCIES.lock.json) 及 [组件声明](../THIRD_PARTY_NOTICES.md)，按记录的公开来源取得依赖。
2. 有 Git 基线的组件先检出对应提交，再将 `upstream/overlays/<组件>/` 的受审文件复制到同名相对路径。替换文件应连同其上游许可证保留，不能直接用于其他版本。
3. `upstream/snapshots/` 是必要的非 Git 源码快照；基线不明的部分需要另外核对来源与兼容性，安装同名版本不能保证重建相同代码。
4. 安装各组件声明的 Python/Node 依赖，按上游说明构建管理界面与插件前端。仓库不携带现成的运行环境或第三方构建包。

锁文件没有列明的提交、校验值或完整包版本不能自行视为已验证。模型、字体和可选素材应另外取得并遵守各自许可。

小黑盒自有代理连接池补丁还要求精确的 HTTP 库版本、loopback 代理和客户端结构，详见 [故障恢复的适配边界](FAILURE_RECOVERY.md#tls-握手失败与连接池耗尽)。先验证兼容性，不要删除保护检查来适配未知环境。

自学习插件不分发旧的 `web_res/static/dashboard/` 编译界面，其中捆绑依赖的版本未能确认；需要该界面时，从保留的 `web_src/` TSX 源码和依赖锁重新构建。RVC 的旧 `tools/uvr5/` 分离子树因许可待核未分发，当前翻唱封装使用 `pymss` 路径；需要其他分离器时应另行取得并核对其许可与兼容性。

## 3. 放置本地扩展

| 归档目录 | 新环境中的用途 |
| --- | --- |
| `plugins/<插件名>/` | 将已包含的 10 个插件按需要放入新 AstrBot 实例的插件目录，按所用宿主版本安装其依赖 |
| `scripts/` | 放入自行建立的运维目录，逐项适配配置路径和调用的服务位置 |
| `integrations/native-bridge/` | 结合兼容上游安装原生集成源码和辅助脚本 |
| `upstream/local/` | 为需要的本地服务建立独立安装及数据目录 |
| `examples/` | 复制为仓库外的本地配置，填写自己的值 |

归档布局与运行布局不同，脚本内的路径占位符需要改为新环境的真实路径。部分身份和来源校验也已脱敏，需重新配置；这些文件不能未经审阅直接启动。

启用 `scripts/BiliScrollMcp.py` 时，其预期入口位于新环境的 `data/dsh-bili-scroll/bili-duty/mcp_server.py`。从受审的 `dsh-bili-scroll` 源码快照中取得 `vendor/bilibili-mcp/` 所需源码，在新建的 `bili-duty/` 目录按调用关系放置；不要复制旧运行数据目录来满足该路径。

原生桥依赖的上游包不在仓库内，现有材料不保证足以重建其集成。取得可信基线并完成兼容性核对后，审核全部参与加载的文件，重新生成匹配的完整性清单；不要通过删除哈希或来源检查来绕过启动失败。

## 4. 配置自己的身份、服务与授权

从 `examples/` 重新建立本地配置，填写自己的管理员身份、服务地址、凭据引用和路径。人格与回复提示词由使用者自行编写；归档不提供原用户的默认人格或聊天内容。

配置中的示例字段仅解释结构，不代表所有组件已经支持统一环境变量或统一配置加载方式。以相应组件实际读取逻辑为准。凭据应保存在仓库外的本地秘密存储或受保护配置中。

好友人格投影、其私人指纹及漫画角色参考清单未导出，对应分支不能靠当前占位直接运行。需要这些功能时，应在本地建立自己的资料，并按代码的验证规则配置新的受审清单；原私人资料和角色参考素材无法从本仓库恢复。

初始阶段保持消息发送、评论、发帖、资料修改、定时任务、自动恢复和其他自动外部操作关闭或未授权。按需要分别配置平台登录与功能开关，逐项确认目标、权限和额度后，再由使用者明确启用需要的能力。开启阅读权限不自动授予评论或分享权限。

原有授权和业务状态没有导出。新环境不应尝试接续旧任务、补发历史消息或根据空白账本推断某项操作从未发生。

## 5. 验证边界

先完成静态语法、依赖、配置结构及合成数据的离线验证。检查脚本或测试是否会导入后启动后台循环、登录平台、调用模型或真实发送；这类操作应单独安排，不能作为阅读源码的隐含步骤。

需要实际运行时，分别验证宿主启动、插件加载、平台连接、业务开关与具体投递。状态显示在线不能替代功能验收；某一条成功回执也不能证明所有功能已测试。

本归档没有通过重启现有服务、发送测试消息、调用模型、公开发布或迁移私人数据来完成验证。真实端到端测试及平台使用责任由新环境的使用者自行安排。
