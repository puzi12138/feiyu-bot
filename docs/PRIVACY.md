# 隐私排除与提交检查

本仓库采用新建脱敏源码快照的方式公开归档，不携带原运行目录或上游仓库的 Git 历史。筛选范围包括代码、注释、配置 schema、依赖清单、测试与文档，不能只按文件扩展名判断安全。

## 排除内容

- 账号、个人或群标识、私人地址、真实机器路径及与特定用户关系有关的配置。
- API Key、认证令牌、密码、Cookie、登录二维码、会话文件和浏览器/客户端档案。
- 实际配置、环境文件、授权、队列、发送意图、回执、用量与账单、事件及其他运行状态。
- 数据库及 WAL/SHM、聊天正文、私有记忆、人格、阅读笔记、日记和实际提示词配置。
- 日志、私有维护记录、审计材料、备份、缓存、临时目录、下载和历史构建包。
- 图片、音频、视频、角色参考、语音与训练素材、模型权重及平台/运行时二进制。
- 原运行目录的 `.git`、虚拟环境、`node_modules` 和第三方发行包。

保留的 JSON/YAML 是经过审阅的源码 schema、依赖清单或重新构造的模板。`.sql` 可能是必要的建表源码；名为 `models/` 的目录也可能是 Python 数据模型源码，不能据目录名直接删除。

分发范围另排除自学习插件的旧 `web_res/static/dashboard/` 编译界面，以及 RVC 的旧 `tools/uvr5/` 子树，分别涉及捆绑依赖版本无法确认和许可待核。前者保留 `web_src/` 源码及依赖锁供重建，后者不影响当前使用 `pymss` 的翻唱封装路径；这不构成对其他资源或依赖的额外许可。

## 模板与源码脱敏

模板使用虚构占位值，外发和自动任务保持关闭或未授权；不从真实配置删掉几个字段后直接复制。私人提示词、真实消息和事故案例不作为示例。

替换代码中的身份、路径、地址或提示词可能影响来源校验、权限判断、指纹及文件哈希。脱敏归档允许保留这种重建缺口，应在新环境重新审阅配置和完整性清单，不能默默放宽原有检查。

有已知上游基线的本地修改以替换文件保存，避免差异文件的删除行泄露旧内容。非 Git 依赖只保存经过筛选的必要源码，其来源和可复现程度按锁文件中的已知信息描述。

## 后续提交

`.gitignore` 用于减少误提交，不能清理已经进入 Git 索引或历史的内容，也不能证明所有源码都不含秘密。提交前检查新增文件清单和完整差异，尤其关注 schema 默认值、测试夹具、URL、注释、锁文件和错误示例。

扫描发现疑似秘密时，不要把命中值复制到 issue、提交说明或审计输出。先将相关内容移出待提交范围，确认需要替换的配置与凭据；如果真实秘密已经暴露，应在对应服务撤销或轮换，并清理远端历史中的副本。不要只删除当前文件后继续使用原凭据。

公开仓库中的文件可被任何人取得。登录态、聊天、密钥与其他私人数据均不应进入提交；后续提交和分发仍需核对隐私与组件许可。四个未确认再分发许可的插件仅保留外部来源记录，不复制其源码或本地修改，详见 [组件声明](../THIRD_PARTY_NOTICES.md)。公开可访问的上游仓库不等于已授予再分发许可。

## 已知局限

自动扫描和人工审阅不能给出绝对无隐私残留保证。第三方源码还可能包含自己的示例和遥测行为，安装依赖或运行脚本前需审阅实际网络与数据行为。归档的过滤不改变上游服务条款，也不证明某个平台账号或外部操作已经获得授权。
