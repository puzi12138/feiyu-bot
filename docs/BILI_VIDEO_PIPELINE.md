# B站视频画面分析与证据边界

自动浏览、手动视频链接分析和专门音画研究，在需要新的画面分析时优先共用 `dsh-video-storyboard`。字幕足以回答的路径仍可直接使用字幕，不强制下载视频。此文描述源码行为，不代表新安装环境已启用自动业务或完成真实视频验收。

## 接入方式

| 入口 | 新画面处理 | 保留的流程 |
| --- | --- | --- |
| B站插件自动浏览、手动或链接分析 | 每个可用片段调用共享桥，目标为一张九格分镜 | 字幕策略、BV锁、成功缓存、已处理去重、显式重看和原媒体回退 |
| 专门音画研究 | 共享桥输出最多两张各九格的分镜，再交现有视觉服务 | 真实音轨ASR、旧分析缓存、原阅读及手账路径 |
| 自动私人手账 | 不把分镜摘要直接改写为字幕或作者原话 | `dsh-bili-humanism` 的原来源链、A1/A2证据检查和推荐条件 |

共享桥位于 [BiliStoryboard.py](../scripts/BiliStoryboard.py)。B站插件的 [storyboard_bridge.py](../plugins/astrbot_plugin_bilibili_ai_bot/core/storyboard_bridge.py) 固定加载这个独立模块，不初始化另一插件。音画研究入口位于 [video_media.py](../plugins/feiyu_steward/video_media.py)。

桥接层只接收所属目录内的本地媒体，独立创建临时目录，校验输入来源、PNG和清单；固定使用本地Node、FFmpeg及FFprobe，并关闭分镜工具自带转录。它不接收浏览器Cookie、模型凭据或远程视频地址。依赖源码和许可仍沿用仓库已有的 [来源锁](../upstream/DEPENDENCIES.lock.json) 与 [组件声明](../THIRD_PARTY_NOTICES.md)，本次未升级第三方版本。

迁移时，先取得并安装依赖，再将 `scripts/` 和插件映射到各自运行目录。源码中的安装根路径是需要适配的部署约定；不要直接从仓库根目录导入插件，也不要关闭所属目录和来源校验以绕过安装问题。具体准备见 [重新安装与配置](SETUP.md)。

## 音频、缓存与手账

- 分镜工具负责画面抽样，音频仍由原真实音轨ASR处理：短视频使用可用音轨，长视频抽取开头、中段和结尾，合计最多600秒；不等于理解完整配乐、语气或全部对白。
- 有效旧缓存继续沿用原采样方法和范围；新视觉缓存校验源文件元数据、图片及清单哈希。变化或不完整的缓存保留并报告，不自动覆盖未知结果。
- 自动手账继续原来源和证据链。分镜图及视觉摘要不是字幕、作者逐字原话或已写入笔记的证明。
- 专门音画研究的新分镜结果在写手账前核对证据时间与已记录取帧点、音频起点或来源文字定位；不匹配时保留总结但不写笔记。时间匹配不是语义正确性或精确解码帧时间的证明。
- 各入口保留原有缓存与任务边界，没有新增跨入口的全局去重服务；不能保证不同入口只下载或只调用模型一次。既有发送保护和结果不明时的阻断保持。

## 覆盖说明与失败处理

纯分镜、分镜混合原媒体回退、全部原媒体回退分别记录实际方法。覆盖计数的分母是本次成功取得的可用片段，不代表全片连续观看；九格及十八格是目标布局，子网格和实际采样范围以输出清单为准。中点取帧记录近似定位，不伪称精确解码帧时间。

原生视频分析在分镜失败时保留原媒体直读或截帧回退。取消后不继续启动新回退；并行音画分支会回收本地任务，但不能据此保证已发给远端的请求撤回。本次未增加模型重试器，也不回放历史任务。

## 验证范围

原生专项检查27项通过；音画研究检查33项通过，2项实际符号链接检查受Windows权限限制跳过，其替代路径解析检查通过；手账覆盖说明的6个分支检查通过。共享工具处理本地40秒合成视频，得到一张九格和两张九格输出。

以上不包含真实视频、真实ASR、视觉模型或消息发送的人工端到端验收，也不等于从公开仓库完成重建验证。旧模型路由套件的3项失败及1项错误在未修改基线中同样存在，未计入通过结论。最长45分钟的视频准入限制不保证每条视频都能在分镜处理预算内完成。
